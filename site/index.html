The problem

Agents write fast. They don't look back.

Copies of what's already there

It writes a new formatTimeAgo when the repo already has timeAgo, because it never saw it.

Holes it can't see

A hard-coded secret, a route with no login check, a socket event that lets anyone delete anyone's message.

Code nobody calls

Old helpers, unused files and packages pile up, until nobody knows what's safe to change.

How it works

It speaks up at four moments. Otherwise, it's quiet.

When you ask

The code you already have

Attentry tells Claude which helpers and routes in the repo match your request, so it plans with them.

Attentry: the repo already has code related to this request: - `timeAgo` in src/utils/time.js:1 - GET /api/rides/:id in server.js:11

Before an edit

No second copy

If Claude is about to write a function the repo already has, it hears where the existing one is.

Attentry: `formatRidePrice`: the repo already has `formatPrice` (src/utils/money.js:2, used in 4 places). Import it.

After an edit

Only what this edit added

New problems, once each, in a few lines. A clean edit gets nothing at all, and old issues never nag.

Attentry: this edit added 1 problem: server.js:7 socket event "message:delete" loads a record by an id the caller sends without checking it belongs to the caller

At the end

A change card for you

What changed, what it added or fixed, and whether the tests passed. Read it in ten seconds.

Attentry change card - Changed: 3 files - Problems: none added - Tests: passed

What it catches

The mistakes AI-built apps make most.

Security, door by door

Routes, socket events, tRPC, GraphQL and server actions with no login check, no owner check, or no rate limit. Secrets in code, injection, XSS.

Crash risks

Async handlers with no error handling, JSON.parse on outside data, exiting the process from a request.

Frontend and backend

Calls to routes that don't exist, the wrong method, and routes nothing calls any more.

Database

Money stored as floats, queries inside loops, trees fetched one level at a time.

Copies and dead code

Exact and drifted copies, unused files, packages and functions, with what replaced them.

Hotspots

Complex files that change all the time: where a change is most likely to break something.

JavaScript, TypeScript and Python. What it can't check yet, it says so, so "no issues" never means "not looked at".
