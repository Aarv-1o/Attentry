Not a wrapper around another model. Attentry is its own static analyzer: it learns your repo's routes, functions and imports, checks every edit for security holes, copied code and dead code, and tells the agent so it can fix them before anything ships. No API key, no tokens, nothing leaves your machine.

Written up by SmartScope and Emergent

The problem

How it works

Four moments. Otherwise, quiet.

When you ask

The code you already have

Your agent hears which helpers and routes in the repo match your request, so it plans with them.

Attentry: the repo already has code related to this request: - `timeAgo` in src/utils/time.js:1 - GET /api/rides/:id in server.js:11

Before an edit

No second copy

About to write a function the repo already has? Your agent hears where the existing one is.

Attentry: `formatRidePrice`: the repo already has `formatPrice` (src/utils/money.js:2). Import it.

After an edit

Only what this edit added

New problems, once each, in a few lines. A clean edit gets nothing at all; old issues never nag.

Attentry: this edit added 1 problem: socket event "message:delete" loads a record by an id the caller sends without checking it belongs to the caller

At the end

A change card for you

What changed, what it added or fixed, and whether the tests passed. Ten seconds to read.

Attentry change card - Changed: 3 files - Problems: none added - Tests: passed

Tests

Your tests run while the agent works.

Attentry finds your test command, like npm test or pytest, and runs it in the background as the agent edits. It reads which routes your tests reach without ever starting your app.

Several projects

A folder of projects? Pick the one to check.

Editors often get opened one folder too high: Downloads, or a folder of checkouts. If that folder holds one project, Attentry finds it by itself. If it holds several, pick one from the menu at the top of the panel. Your agent's checks follow the same choice, and it's remembered for that folder.
